# Evidence-led operations briefing

Use the exact client/agency scope and current requested period. Read saved task/context records first. Consult only connected, authorised email/calendar/CRM/document routes relevant to the request; a named app or installed skill is not proof of access. Missing systems get an explicit coverage note, not an invented empty inbox or zero overdue invoices.

Distinguish what needs the owner’s decision, what is already assigned, what is blocked, and what is awaiting QA/review. Attach source/task IDs, timestamps and next actions. Meeting preparation uses actual agendas and client records; financial follow-ups use the real due date, invoice, payment state and approved contact. Do not infer that a booking means revenue or that a missing payment sync means an unpaid bill.

Draft useful reply/follow-up text when requested and supported by evidence. Keep draft, internally reviewed, sent and confirmed states separate. Sending, scheduling and external financial actions follow existing explicit task authorisation and connector capabilities; do not request a new blanket global permission. Summarise meaningful changes and unresolved issues compactly. This method does not create daily automation, change global instructions, connect accounts, rewrite personal preferences or operate across unrelated clients.

[Source review and adaptation](references/source-review.md) records the public guidance and its limits.

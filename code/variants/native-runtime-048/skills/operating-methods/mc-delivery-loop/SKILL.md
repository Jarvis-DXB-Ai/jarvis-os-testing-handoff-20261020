# Evidence-led delivery loop

Use the owner’s existing brief, exact client context and output format. Capture the useful objective, must-haves, constraints and observable acceptance conditions before substantial production. Reuse supplied answers; ask only when a missing decision materially blocks useful work. Do not force an interview, arbitrary checklist length or a separate planning session for a small request.

## Produce and check
- Complete the requested artifact within the existing scope. A planning-only assignment ends at its agreed plan; an implementation assignment continues through implementation and relevant verification.
- Keep acceptance claims separate from verification. For each material condition retain the source/artifact revision, observation or measurement, result, and remaining defect. No evidence means unassessed or blocked, not pass. QA passing is separate from owner approval and publication.
- A failed check becomes a precise fix: affected condition, evidence, smallest necessary correction and how to verify it. Preserve already-correct independent work. Recheck the repair and affected dependencies; preserve prior evidence only when its source/artifact is unchanged.
- Prefer the smallest relevant check and team. Independent departmental QA stays separate from the author. A self-check is not an independent reviewer or a second model.

## Stop and hand off
Finish when the requested conditions are satisfied. Stop unnecessary polishing and repeated successful tests. An unchanged failure across three attempts requires a different approach or a specific blocker/decision; three is a ceiling, not an instruction to consume retries. Unknown or unacknowledged native actions require reconciliation before any retry. Respect an earlier engine stop or lower execution limit. This method does not start agents, rerun stages, schedule work, increase budgets or bypass review gates. Match strict coordinator response schemas; do not add checklist fields they do not accept.

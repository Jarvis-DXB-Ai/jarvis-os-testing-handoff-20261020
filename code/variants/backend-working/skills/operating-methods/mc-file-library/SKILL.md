# Careful file curation

Establish the exact selected source folder(s), client/entity, destination and intended use from the existing request. Reuse the client’s current Brain/library taxonomy and source-of-truth rules. Inspect a bounded inventory and representative files; filenames alone do not establish identity, authenticity or approval.

Use copies or reference pointers while preserving originals. Propose a concrete grouping when the desired structure is unclear; proceed when the owner has already authorised the destination and organisation. Do not add a second permission step for the same reversible curation.

For each retained item record client ID, collection, title, original path/URL, source date, SHA-256 or version, why it helps, authenticity, review/approval and rights. Distinguish current working files, earlier versions, inspiration and approved masters. Preserve original filenames in source copies; map collisions through separate subfolders or explicit item IDs, never silently overwrite or rename originals. Equal filenames are not duplicates; compare hashes. Unclear identity or permissions goes to a named review queue, outside active brand truth.

Copy only selected useful material, not the whole personal brain or another client’s archive. Reject path traversal, symlink escapes and credential/vault material. Keep snapshots dated; do not claim live sync. Count saved items separately from versions/metadata/archive files and compare copied hashes with sources before claiming success. Return the catalogue, item counts, exceptions and actual storage locations. Downloads, upload, delete, move, mass reorganisation or broad filesystem access require their own task scope and available tools; this skill supplies none.

[Source review and adaptation](references/source-review.md) records the public guidance and its limits.

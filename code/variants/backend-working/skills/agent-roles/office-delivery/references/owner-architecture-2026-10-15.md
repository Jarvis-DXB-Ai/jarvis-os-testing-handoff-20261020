# Owner architecture: delivery

Use the relevant decisions below for this role. Current owner instructions and approved client scope override historical defaults.

Join the agreed deliverable and owner to its production dependency, review route, expected format and actual file. Batch independent work only when tools and inputs permit; name blocked dependencies rather than treating parallelism as extra capacity. Measure delivery time, rework and queue delays before forecasting capacity. A dashboard, model response or skill file is not proof of a functioning delivery workflow. Consolidate evidence and essential questions for the COO instead of forwarding a raw stream of agent updates.

Follow the actual assigned execution stage; this method does not bypass review gates or grant tools, paid calls, messaging or publication. Pinned owner sources are recorded in the skill registry.

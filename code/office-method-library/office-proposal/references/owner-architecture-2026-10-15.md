# Owner architecture: proposal

Use the relevant decisions below for this role. Current owner instructions and approved client scope override historical defaults.

Build the proposal around sourced diagnosis → opportunity → recommended strategy → service implementation → intended outcome → commercial terms. For each included service make quantities, formats, period, dependencies and exclusions agree with the same scope revision. Reconcile the actual proposal and owner-approved onboarding scope; retain both if they differ and surface the material decision. A recommendation is not a purchased service. Do not import the legacy Essentials/Enterprise prices, setup terms, deliverable counts or automatic three-option structure. The original method's useful distinction is directional pre-sign strategy versus deeper post-onboarding strategy, not a promise that untested capabilities already operate. Keep the client presentation visually clear and premium, with internal source/workpapers separate; retain disclosures needed to assess the offer.

Follow the actual assigned execution stage; this method does not bypass review gates or grant tools, paid calls, messaging or publication. Pinned owner sources are recorded in the skill registry.
